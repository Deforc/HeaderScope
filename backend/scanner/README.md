# Сборщик подключений

Модуль Андрея Игнатьева: C++20, Clang LibTooling. Возвращает общий `ScanResult` из
`headerscope/analysis.hpp`; цель для подключения — `HeaderScope::scanner`.

## Сборка

Нужны CMake 3.21+, C/C++ компиляторы и **LLVM и Clang одной версии, 18 или новее**,
включая заголовки и библиотеки LibTooling. Системный Apple Clang сам по себе
не содержит LibTooling. Qt для проверки сборщика не нужен.

macOS / Homebrew:

```sh
brew install cmake llvm@18
cmake -S . -B build-core -DHEADERSCOPE_BUILD_APP=OFF -DHEADERSCOPE_BUILD_SCANNER=ON \
  -DLLVM_DIR="$(brew --prefix llvm@18)/lib/cmake/llvm" \
  -DClang_DIR="$(brew --prefix llvm@18)/lib/cmake/clang"
cmake --build build-core
ctest --test-dir build-core --output-on-failure
```

Ubuntu 24.04:

```sh
sudo apt-get install cmake llvm-18-dev libclang-18-dev clang-18
cmake -S . -B build-core -DHEADERSCOPE_BUILD_APP=OFF -DHEADERSCOPE_BUILD_SCANNER=ON \
  -DLLVM_DIR=/usr/lib/llvm-18/lib/cmake/llvm \
  -DClang_DIR=/usr/lib/llvm-18/lib/cmake/clang
cmake --build build-core
ctest --test-dir build-core --output-on-failure
```

На Windows нужны development-библиотеки LLVM/Clang, собранные совместимым
компилятором; одного установщика `clang.exe` недостаточно. Укажите `LLVM_DIR`
и `Clang_DIR` своего комплекта. При многоконфигурационной сборке добавьте
`--config Debug` к сборке и `-C Debug` к CTest.

## API для окна и интеграции

```cpp
#include <headerscope/scanner.hpp>

auto result = headerscope::scanProject("/project/build/compile_commands.json");
// Можно передать и каталог /project/build.
```

Существующий вызов `scanIncludes(path)` сохранён и возвращает тот же результат
с параметрами по умолчанию. Сборщик и обе консольные команды включаются опцией
`HEADERSCOPE_BUILD_SCANNER=ON`; без неё ядро графа и демоданные собираются без LLVM.

Вызов синхронный: окно должно запускать его в фоновом потоке. Сборщик не зависит
от Qt, не строит графовые индексы и не меняет исходники. Он не запускает
компилятор из базы как внешний процесс и не создаёт объектные файлы.

- Учитываются `directory`, `arguments` или `command`, `-I`, `-isystem`, `-D` и
  остальные параметры Clang. Относительные пути разрешаются в каталоге команды.
- Встроенные заголовки (`stddef.h`, `stdarg.h` и другие) берутся из комплекта
  LLVM, выбранного при сборке. Явный `-resource-dir` из базы имеет приоритет.
  Этот комплект заголовков должен оставаться доступен при запуске приложения.
- Результат объединяет активные подключения всех единиц трансляции и всех
  записанных вариантов команд. `#if 0` не создаёт ребро.
- Идентификаторы файлов — канонические абсолютные пути. Строки физические,
  с единицы; директива `#line` их не подменяет.
- Повторы одной директивы при анализе разных исходников объединяются; подключения
  того же заголовка на разных строках сохраняются. Порядок файлов и рёбер стабилен.
- Исходник без подключений тоже входит в `files`. Все концы рёбер входят в `files`.
- Системные заголовки и связи из них по умолчанию исключены. Для их включения:
  `scanProject(path, {.includeSystemHeaders = true})`.
- Ненайденный заголовок не создаёт вымышленный файл: ошибка Clang возвращается
  в `diagnostics` с файлом и строкой, когда они доступны. Предупреждения не
  меняют успешный статус; ошибки препроцессора, синтаксиса и драйвера меняют.
- `complete` — анализ без ошибок; `partial` — хотя бы один исходник начал
  анализироваться, но были ошибки; `failed` — нет доступного для анализа исходника
  либо база отсутствует, повреждена или пуста. Непустые `files` при `partial`
  могут состоять только из исходников без найденных подключений.

Пределы: показываются именно текстовые директивы `#include`/`#include_next`/
`#import`. Принудительный `-include` без физической директивы не получает
вымышленную строку. Рёбра внутри уже собранных PCH/модулей не восстанавливаются;
для полного графа используйте команды без PCH и модулей. Граф объединяет варианты
компиляции: связи из разных вариантов не обязательно активны одновременно.

## Демо без интерфейса

Из корня репозитория:

```sh
cmake -S demo/include-chain -B build-demo
cmake --build build-demo
build-core/backend/scanner/headerscope_scan build-demo > build-demo/scan.json
```

JSON содержит `status`, `files`, `edges` и `diagnostics`. Ожидаются ровно
`main.cpp:1 → a.h` и `a.h:3 → b.h`. Затем включите дополнительную зависимость:

```sh
cmake -S demo/include-chain -B build-demo -DHEADERSCOPE_DEMO_EXTRA=ON
build-core/backend/scanner/headerscope_scan build-demo
```

Добавится `a.h:6 → extra.h`. Чтобы увидеть системные подключения, добавьте
`--include-system-headers`. Код выхода: `0` для `complete`, `1` для `partial`/
`failed`, `2` при неверных аргументах. Сообщения Clang могут появляться в stderr,
stdout содержит только JSON. На Windows у исполняемого файла суффикс `.exe`.

## Проверки

CTest запускает 11 сценариев: совпадение с общими демоданными, условное `-D`,
относительные пути с пробелами и макросы, несколько исходников/вариантов команд,
сохранение разных строк и удаление межфайловых дублей, диагностика отсутствующего
заголовка, предупреждения и синтаксические ошибки, фильтр системных заголовков,
защищённые циклы и физические строки, строка `command`, отсутствие базы/неверный
JSON/пустая база/отсутствующий исходник, встроенные заголовки Clang.
