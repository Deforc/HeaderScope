# Архитектура HeaderScope

HeaderScope работает локально. Сборщик получает команды компиляции проекта и извлекает прямые подключения. Ядро строит граф в памяти. Главное окно запускает анализ и передаёт результаты виджету графа.

```text
compile_commands.json → сборщик Clang → ScanResult → ядро графа → окно Qt
                                              └── диагностика → окно Qt
```

## Разделение модулей

| Кто | Каталог | Результат |
| --- | --- | --- |

| Андрей Игнатьев | `backend/scanner/` | Сборщик C++20 на Clang LibTooling. Принимает путь к `compile_commands.json` и возвращает `ScanResult`. Подключение LLVM и Clang настраивается в CMake этого модуля. |
| Иван Тюрин | `backend/graph/` | Ядро C++20 на стандартной библиотеке. Строит граф из `ScanResult`, ищет прямые и обратные связи, кратчайшие пути обходом в ширину и циклические группы алгоритмом Тарьяна. |
| Владимир Брежнев | `app/window/` | Главное окно Qt Widgets. Выбор проекта, анализ в фоне, список файлов и зависимостей, показ диагностики. |
| Алексей Дмитриев | `app/graph_view/` | Виджет Qt Widgets для графа, цепочек и проверки нового подключения. Сценарий для защиты. |

CMake-цели `HeaderScope::scanner`, `HeaderScope::graph` и `HeaderScope::graph_view` уже подключены. Добавляя код своего модуля, замените его `INTERFACE`-цель на библиотеку с исходниками в том же `CMakeLists.txt`. Сохраните имя цели, чтобы соседние модули подключались без изменений.

## Формат результата

Общие типы объявлены в [analysis.hpp](../include/headerscope/analysis.hpp).

- `IncludeEdge{includer, included, line}` означает, что в файле `includer` на строке `line` находится директива, которая подключает файл `included`. Нумерация строк начинается с 1.
- Идентификатор файла — нормализованный абсолютный путь. Короткое имя можно использовать в интерфейсе. Все файлы, встречающиеся в связях, также присутствуют в `files`. Анализируемый исходник без подключений тоже входит в `files`.
- Сборщик сохраняет директивы на разных строках. Ядро объединяет одинаковые пары файлов в одно ребро для обхода.
- `ScanStatus::complete` означает успешный анализ, `partial` — пригодный к просмотру граф с пропущенными данными, `failed` — отсутствие пригодного результата. Ненайденный заголовок попадает в диагностику. Для него не добавляется ребро к вымышленному файлу.
- Для прямой зависимости стрелка идёт от включающего файла к заголовку. Для поиска файлов, затронутых изменением заголовка, ядро идёт по стрелкам в обратную сторону.

## Как начать параллельно

Андрей проверяет сборщик на исходниках из `demo/include-chain/`. Иван, Владимир и Алексей могут сразу подключить цель `HeaderScope::demo_fixture`, включить заголовок `<headerscope/demo/fixture.hpp>` и вызвать `headerscope::demo::makeIncludeChain(demoDirectory)`. Функция возвращает тот же `ScanResult`, который позже отдаст сборщик. Она не читает исходники. Для условного подключения вызовите её с аргументом `true`.

1. В базовой конфигурации ожидаются ровно две связи: `main.cpp:1 → a.h` и `a.h:3 → b.h`.
2. С флагом `HEADERSCOPE_DEMO_EXTRA` добавляется `a.h:6 → extra.h`.
3. Для `b.h` ожидаются прямой зависимый файл `a.h`, косвенный зависимый файл `main.cpp` и цепочка `main.cpp → a.h → b.h`.
4. Предложение добавить `b.h → a.h` должно показать будущий цикл `b.h → a.h → b.h`. Проверка ищет путь от предлагаемого заголовка обратно к включающему файлу. Она не меняет исходники или исходный граф.
5. Чтобы проверить уже существующий цикл, добавьте `b.h → a.h` в копию демоданных. Алгоритм Тарьяна должен вернуть одну циклическую группу из `a.h` и `b.h`, а приложение — показать пример замкнутой цепочки.
