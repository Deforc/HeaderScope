# Главное окно HeaderScope

Окно использует общий `ScanResult` и существующий `DependencyGraph`. Бэкенд и
каталог `app/graph_view` не изменяются.

## Язык интерфейса

В верхнем правом углу выберите `Русский` или `English`. Язык меняется сразу,
включая подписи загруженных зависимостей, циклов и статусы анализа. Выбранный язык
сохраняется между запусками. Переключение не запускает анализ заново и сохраняет
выбранные файлы, вкладку и подсветку графа. Сообщения самого Clang показываются
в исходном виде; сообщения приложения доступны на обоих языках.

## Запуск

Нужны CMake 3.21+, компилятор C++20 и Qt 6.5+ (Widgets, Concurrent; Test для тестов).
Из корня репозитория:

```sh
cmake -S . -B build -DCMAKE_PREFIX_PATH=/path/to/Qt/6.x/kit
cmake --build build
ctest --test-dir build --output-on-failure
```

На Windows запустите `build/app/window/HeaderScope.exe` (либо подкаталог Debug/Release).
На macOS — `build/app/window/HeaderScope.app`. Для сборки без тестов используйте
`-DBUILD_TESTING=OFF`. При запуске нужны библиотеки Qt из выбранного комплекта.

Нажмите «Папка…» или «compile_commands.json…» — анализ запустится сразу после выбора.
Затем выберите файл слева: справа появятся его подключения и прямые/косвенные
потребители. Наведите курсор на зависимый файл, чтобы увидеть полную цепочку. Двойное
нажатие на строку зависимости или нажатие на вершину графа выбирает файл. Поиск
фильтрует список, колесо масштабирует граф, перетаскивание перемещает его.
Переключатель «Тёмная тема» меняет оформление (нужен Qt 6.8+; по умолчанию
используется системная тема).

Для реального проекта включите `HEADERSCOPE_BUILD_SCANNER=ON` и настройте LLVM/Clang
по корневому README. Выберите папку с `compile_commands.json` либо сам файл в
каталоге сборки и нажмите «Анализировать». Без сборщика анализ выдаёт
объяснение в диагностике. Неполный результат остаётся доступен; после неудачи
старые результаты очищаются. Одновременный повторный запуск блокируется.

## Группировка графа по папкам

По умолчанию граф показывает свёрнутые папки верхнего уровня и отдельные файлы
в корне проекта. Если в корне больше 12 файлов, они объединяются в блок
«Файлы в корне». Папки содержат все вложенные файлы, включая изолированные.
Внешние заголовки остаются отдельными группами по своему каталогу.

- Двойной щелчок по папке раскрывает один уровень: файлы и вложенные папки.
- Правая кнопка на файле или вложенной папке позволяет свернуть родительскую папку.
- «Свернуть всё» возвращает начальный обзор; снятие «Группировать по папкам»
  показывает все файлы. Повторное включение сохраняет раскрытые ранее ветви.
- Выбор файла слева, цепочки, конкретного цикла или проверяемого подключения
  раскрывает нужные каталоги. В начальном обзоре автоматически выбранный файл
  лишь подсвечивает содержащую его папку.

Между видимыми блоками рисуется одна стрелка на направление. Число на ней —
количество уникальных пар файлов, а не директив на разных строках. Наведение
показывает примеры связей. Внутренние связи свёрнутой папки указаны в её подписи;
они не превращаются в вымышленные петли или циклы между папками. Цвета подсветки
сохраняются при объединении связей. Анализ, диагностика и экспорт используют
исходный граф файлов: группировка меняет только отображение.

Схема размещается по уровням зависимостей с переносом длинных цепочек. При
раскрытии сохраняется читаемый масштаб; граф можно перемещать перетаскиванием и
масштабировать колесом. «Уместить граф» явно показывает всю схему целиком.
При новом анализе раскрытие сбрасывается, выбранный режим группировки сохраняется.

## Точка интеграции графа

`GraphPlaceholder` — временное представление на QGraphicsView внутри модуля окна.
Оно не реализует задачу Алексея целиком. Для подключения будущего виджета из
`HeaderScope::graph_view` замените этот тип и сохраните три операции:

- `setResult(const ScanResult&, const std::filesystem::path& root = {})` — передать результат и корень проекта для группировки;
- `selectFile(const std::filesystem::path&)` — подсветить выбранный файл;
- сигнал `fileActivated(const QString&)` с полным UTF-8 путём — выбрать файл в окне.

`fitGraph()` используется кнопкой «Уместить граф». `highlightChain(...)` подсвечивает
набор рёбер цепочки до зависимого файла.
`showProposedInclude(...)` рисует пунктиром предлагаемое подключение.

## Зависимости выбранного файла или папки

Один щелчок по свёрнутой папке на графе или по каталогу в дереве слева показывает
её зависимости справа. «Зависимые файлы» перечисляет внешние файлы, которым
папка нужна прямо или косвенно; «Включает напрямую» — заголовки за пределами папки,
которые подключаются из неё. Внутренние файлы не включаются в эти внешние списки.

Для отдельного файла отображаются его прямые подключения и все потребители.
У исходника вроде `main.cpp` список потребителей часто пуст — это нормальный
результат. Для просмотра влияния изменений выберите общий заголовок.
В строках используются пути относительно проекта, чтобы различать одноимённые файлы.

Выбор потребителя справа подсвечивает пути к выбранному файлу или границе папки;
выбор прямого подключения подсвечивает соответствующие исходящие стрелки.
Нужные папки раскрываются автоматически, а сама панель сохраняется при смене языка.

## Проверка #include

Вкладка «Проверка #include» отвечает, замкнёт ли новое подключение цикл. Файл
берётся из выбранного слева (его можно сменить в списке), заголовок выбирается
вручную. Новое ребро `файл → заголовок` замыкает цикл, если заголовок уже подключает
файл прямо или косвенно; проверка ищет кратчайший такой путь через `shortestPath`
и не меняет граф. Справа показывается будущий цикл и причина, на графе подсвечен
существующий путь, а предлагаемое подключение нарисовано пунктиром: красным, если
цикл замкнётся, зелёным — если нет.
Для существующей прямой связи вкладка сообщает, что подключение уже есть.
При частичном анализе без найденного обратного пути вкладка сообщает, что в
доступных данных цикл не найден, и убирает пунктирную стрелку.

## Циклы

Вкладка «Циклы» перечисляет все простые циклы по группам, найденным алгоритмом
Тарьяна. Счётчик на вкладке показывает число циклов. Все циклы подсвечены
одновременно, рядом с каждой цепочкой справа показан её цвет. Длинные цепочки
переносятся на несколько строк. Выбор цепочки выделяет её на графе, кнопка
«Показать все циклы» возвращает общий вид с цветными полосами на общих рёбрах.
Чтобы получить цикл на демопроекте, сконфигурируйте его с `-DHEADERSCOPE_DEMO_CYCLE=ON`.

Анализ вызывается через QtConcurrent без захвата окна; QFutureWatcher доставляет
результат в главный поток. Сборщик не предоставляет отмену: повторный запуск
заблокирован до завершения, а завершение процесса может дождаться рабочего потока.
Промежуточный процент не показывается, поскольку API сборщика его не сообщает.

Тесты `window` проверяют зависимости `b.h`, частичный результат, очистку после
ошибки, отсутствующую базу команд, показ цикла и проверку нового подключения (тесты подают фикстуру через `showResult`). Workflow
`Qt main window` собирает и проверяет окно в двух конфигурациях: со сканером и без.

Дополнительные тесты проверяют раскрытие и сворачивание папок, объединение связей,
сохранность внешних и изолированных файлов, выбор вершин, перевод подписей и
обзор из 25 блоков для 5000 файлов. Установив `HEADERSCOPE_GRAPH_PREVIEW` в путь
без расширения при запуске тестов, можно сохранить PNG-примеры обзора и окна.
